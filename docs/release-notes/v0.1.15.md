# LyricBar v0.1.15

Smoother lyric timing, better lyric matching, and GNOME Shell 51 support.

## Added

- Smooth lyric sync: lyric lines now advance on a 100 ms local clock interpolated between position polls, so line changes are no longer tied to the 500 ms polling granularity. D-Bus polling traffic is unchanged.
- Instrumental breaks: timestamped empty LRC lines (e.g. `[01:15.00]`) clear the current lyric during interludes, falling back to your configured fallback mode instead of freezing the previous line.
- GNOME Shell 51 support ([#16](https://github.com/fikrilal/gnome-lyricbar/pull/16)).

## Changed

- LRCLIB matching is more forgiving: decorated titles (Official Video tags, `|` suffixes, bracketed decorations) are sanitized before searching, free-text fallback searches run when field search finds no synced result (only when the track duration is known), and the duration tolerance widens from ±3 s to ±5 s.
- Candidates whose title contains the artist name are accepted when the provider's artist field is a channel or uploader name.

## Fixed

- Transient LRCLIB errors (HTTP 503, timeouts) are no longer written to the local cache with the 6-hour negative TTL, so a temporary outage no longer hides lyrics for hours.
- The interpolated position resists small backward samples from D-Bus latency or throttled players, removing line flicker at lyric boundaries.

## Verification

- `npm run verify` and `npm audit` clean on the release commit; CI green on `main` (38 test files, 432 tests).
- Live LRCLIB evidence: the decorated-title fallback chain resolves synced lyrics; error results are not cached.
- Contributed runtime evidence on GNOME Shell 51.1 (CachyOS, Wayland) with MPRIS players.

## Notes

- Lyric matches cached before this release keep their stored data until the 30-day positive TTL expires; instrumental-break clearing applies to newly fetched lyrics.
- Free-text fallback is intentionally skipped when the player does not report a duration.
